# Reference Games

Reference games are used to understand **why a pattern works**, not to tell Codex to clone another Roblox experience.

For every reference, separate:
- mechanic
- UX/readability
- progression structure
- visual inspiration
- social/retention effect
- what should explicitly not be copied

## Current primary reference

### Steal an Egg

Use primarily for:
- compact shared-world ↔ personal-plot rhythm
- authored plot upgrade positions
- one obvious primary progression station
- visible social progression
- reducing traversal friction as progression grows

Do **not** use it as the visual identity for Roblox IQ.

See `STEAL-AN-EGG.md`.

## How to add a reference

A useful note should answer:

1. What exact player behavior are we studying?
2. What problem does the reference solve?
3. What is the analogous problem in Roblox IQ?
4. Which part of the solution transfers cleanly?
5. Which parts would make Roblox IQ feel like a clone?

## Screenshots / clips

When studying a visual or interaction sequence, prefer a few annotated frames over a raw long video.

Example:

```text
01-before-purchase.png
02-purchase-prompt.png
03-construction.png
04-after-upgrade.png
notes.md
```

The notes should explain the lesson, e.g.:

> The important part is not the exact model; the purchase location is physically obvious before it is owned, and after purchase the plot silhouette visibly changes.

## Rule

Never give Codex only the instruction:

> Make it like Game X.

Give it the actual design property we want to reproduce.
